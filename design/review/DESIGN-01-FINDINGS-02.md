Independent review of the frozen DESIGN-01 specification, recorded on 2026-09-15. Scope is limited to rules with no satisfying implementation and specified operations with no conforming path to perform them. The four frozen models were read in full; related frozen interface and schema provisions were consulted to check possible escape paths. [FINDINGS-01.md](FINDINGS-01.md) supplies the record structure, and [DESIGN-03-FINDINGS-02.md](DESIGN-03-FINDINGS-02.md) supplies candidate claims only. Every finding below was checked against the tag itself. This is neither an amendment review nor an implementation audit. All design `file:line` citations refer to the baseline's blobs, obtainable with `git show design-01-frozen:<file>`; the relative links are document locators. No design changes or resolutions are proposed. Identifiers beginning `D01-F02-` belong to this record and do not reuse the earlier review's identifiers or baseline.

`DEFECT` means a specified rule or operation has no conforming realization in the case identified; it does not report an observed runtime failure. `UNRESOLVED CONFLICT` records incompatible frozen requirements whose reconciliation requires a design decision, without selecting which requirement should change. `REFUTED` means a candidate premise is contradicted by the frozen text. A qualification of a premise does not dispose of an independently established finding. For each local proof, unrelated prerequisites are assumed satisfied so that one startup failure does not become the explanation for every later operation.

**Root-cause assessment: these three do not share one root cause.** The first and third expose a related authority assumption: run-scoped grant machinery is used where kernel holdings or human lifecycle actions must be accounted for. The strongest frozen statement of the activation dependency is [evidence-model.md:95](../evidence-model.md#L95), together with `AX-3` and the resolution algorithm. But “every capability arrives through activation” is not a consistent statement of the whole frozen design: `AX-7` explicitly assigns kernel holdings separately ([authority-matrix.md:18](../authority-matrix.md#L18)), and [authority-matrix.md:34](../authority-matrix.md#L34) names kernel self-holding while [authority-matrix.md:266](../authority-matrix.md#L266) excludes it from run grants. Finding 1 is the verifier's failure to accommodate that distinction; finding 3 is the absence of an exercise path for specified human actions. Finding 2 survives even if all capability checks are assumed satisfied: the prerequisite snapshot needs the entity whose creation it must precede. It is a persistence and referential-integrity conflict, not a consequence of activation. Proximity at startup is not a common causal pattern, so the three are recorded separately.
